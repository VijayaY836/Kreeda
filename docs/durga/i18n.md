# Internationalization (i18n)

How KREEDA handles four languages across both the shell UI and the Vaikunthapali game.

## Languages

| Code | Language | Game name | Script |
|---|---|---|---|
| `te` | Telugu | వైకుంఠపాళి (Vaikunthapali) | Telugu + Telugu numerals |
| `en` | English | Snakes and Ladders | Latin + Arabic numerals |
| `hi` | Hindi | ज्ञान चौपड़ (Gyan Chauper) | Devanagari + Devanagari numerals |
| `ta` | Tamil | பரமபடம் (Paramapadam) | Tamil + Arabic numerals |

## Two i18n layers

The app has two separate translation sets, both in `i18n.ts`:

### 1. `VP_I18N` — game-specific strings

Used by the Vaikunthapali board, game logic, and guide. Contains:

- **Board labels**: virtue names, vice names, Janma/Moksha text, square numbers
- **Digits**: per-language numeral characters for board display (`vpLoc` function maps `1→`౧`, `1→`१`, etc.)
- **Messages**: event text (`{e} rolled {v} → square {p}`), Kreedu speech bubbles, win screen text
- **Guide**: board history, rules, virtue/snake table headers
- **Win screen**: stats templates, notes, button labels

Each language entry is a `VPStrings` object (~80 fields). Template variables use `{name}` syntax, resolved by the `fmt()` helper.

### 2. `SHELL_I18N` — app shell strings

Used by HomeView, GameDetailView, and PlayView. Contains:

- Hero section text (title, description, Kreedu's greeting)
- UI labels ("Choose a game", "Back to all games", "How to play", etc.)
- Map captions
- Play button text

Each language entry is a `ShellStrings` object (~17 fields).

## How language flows through the app

```
App (useState + localStorage)
 ├── LangContext.Provider
 │    ├── HomeView (useLang → SHELL_I18N)
 │    ├── GameDetailView (useLang → SHELL_I18N)
 │    └── PlayView (useLang → SHELL_I18N)
 │         └── Vaikunthapali (own useState + localStorage)
 │              ├── Board (prop: lang → VP_I18N)
 │              ├── Die (reads VP_PIPS, no lang needed)
 │              └── GuideContent (prop: lang → VP_I18N)
```

The App reads the saved language from localStorage on mount and provides it via `LangContext`. The shell components consume the context to display translated UI strings.

The VP game component has its own independent `lang` state because it needs to respond to in-game language switching without resetting the game. When the player switches language inside the game, it:
1. Saves to localStorage (same key as the shell)
2. Calls `onLangChange(lang)` to notify the App shell
3. The shell's LangContext updates, and shell strings re-render in the new language

## Persistence

Language choice is stored in `localStorage` under the key `kreeda-vp-lang`. Both the App shell and the VP game read from and write to the same key, so the choice persists across page reloads and is shared between the shell and game.

## Adding a new language

1. Add the language code to the `Lang` type and `LANGS` array in `i18n.ts`
2. Add a `VPStrings` entry to `VP_I18N` — this is the bulk of the work (~80 fields including board labels, event messages, guide content, win screen text)
3. Add a `ShellStrings` entry to `SHELL_I18N` (~17 fields)
4. The language switcher bar and all components will pick it up automatically

## Numeral system

The `vpLoc(lang, n)` function converts a number to the target language's numeral system by replacing each digit character using the language's `digits` string. For example, Telugu `digits` is `'౦౧౨౩౪౫౬౭౮౯'`, so `vpLoc('te', 42)` returns `'౪౨'`.
